# v3.0.1 — Sensor platform fix

A patch release for a single, high-impact regression in v3.0.0.

## 🐛 Fixed

**The sensor platform failed to set up entirely** — about half the integration's
entities never appeared, `State of Charge` (and `State of Charge Slave N`) among
them.

Three entries in `SENSOR_DEFINITIONS` — *Battery Usable Capacity*, *Average
Discharge SoC* and *Average Charge SoC* — were missing the `device_class` key
that `FossibotSensor.__init__` required with no default. Because the platform
builds its entity list in one comprehension, the first bad entry raised before
`async_add_entities()` was ever reached and took the whole platform down with
it. The only symptom was one terse log line:

```
Error while setting up fossibot platform for sensor:
FossibotSensor.__init__() missing 1 required positional argument: 'device_class'
```

After updating, the entity count goes from 58 back to the full set, and both the
main battery and any expansion packs report SoC again.

`unit` and `device_class` now default to `None`, so a future omission degrades to
a sensor without a device class instead of disabling the platform. A new test
binds every platform's definition table against the signature of the entity it
feeds — it reproduces this failure on the unfixed table and covers the other four
platforms too.

Thanks to **@devon-lopez** for the precise report and root-cause analysis in #36. 🙏

## 🔄 Upgrading

Update through HACS and restart Home Assistant. No configuration changes, no
entity renames.

Closes #36.

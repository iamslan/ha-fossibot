# v3.1.0 — Reliable reconnection, F7200 (protocol V1) support, output switch fix

## 🐛 Fixed

**The integration no longer stalls for minutes after a station comes back.**
When a station was powered off and on again, recovery could sit for about five
minutes without even trying the broker: the recovery handler held the
connection lock and then waited on its own completion. Broker recovery and
station telemetry are now separate: broker setup is serialized, concurrent
recovery callers share one task, a station that stops answering no longer
tears down a healthy subscription, and an online event triggers a fresh read
straight away. (#43, thanks @Deni7)

**Entities no longer show stale values as if they were live.** A station is
available only when it answers the current poll with a fresh input-register
reply. Cached values, retained MQTT messages and settings-only replies do not
restore State of Charge or power readings. With several stations, one that is
off no longer delays the others. (#43)

**`switch.turn_on` no longer turns an output off** (#40). Some firmware,
confirmed on the F2400, flips the USB, DC and AC outputs on *any* write to
their register, whatever the value. The switches now skip the command when the
last fresh reading already shows the requested state. When no fresh reading is
available, the command is still sent.

**Battery Usable Capacity was ten times too high** (#41). Input register 54
counts 0.1 Ah: a 40 Ah F2400-B pack reports 390, now shown as 39.0 Ah. If you
track this sensor in long-term statistics, HA will show a step at upgrade.

## ✨ Added

**Read-only support for protocol V1 stations such as the FOSSiBOT F7200**
(#42, thanks @johnny990). These stations report protocol version 1 in holding
register 7 and use a different register layout, so the V0 table decoded them
wrongly. The integration now detects the profile from the settings frame and
decodes with a V1 table taken from the BrightEMS app: charge inputs per
source, AC output, main and slave SoC, state bits, timers, PV energy counters,
firmware versions and the device clock. New V1 entities: PV 1-4 Input, AC Grid
Power, DC Output Power, PV Energy Today, Device Clock, Grid Discharging, PV
Self-Consumption, Grid Feed Paused and AI Energy Control.

V1 stations get **sensors and binary sensors only**. The connector refuses
every V0 command on a station known to be V1, and the profile is saved so a
V1 station that is off at startup still gets the right entity set.

**Local starts without the cloud.** After the first successful discovery,
device identities, names and Modbus addressing are saved locally (no token, no
readings), so Home Assistant can start and reconnect while the Sydpower cloud
is unreachable. A background check then looks for stations added to the
account; a new one appears after you reload the integration. (#43)

## 🔁 Changed

**Entity names follow the device name** (#39). Entities now use Home
Assistant's device-relative naming, so the display name is
`<device name> AC Output` instead of `Fossibot <MAC> AC Output`. Renaming the
device in Home Assistant renames all of its entities at once and offers to
update their entity IDs. Existing entity IDs and unique IDs are unchanged.

## 🧪 Tests

The suite now runs in CI (`validate.yml`) and covers recovery and lifecycle
(#43), V1 decoding with two frames captured from an F7200 (#42), and
regressions for #39, #40 and #41: 152 tests.
